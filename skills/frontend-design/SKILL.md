# 前端设计：功底、两触点对齐与环节地图

本 skill 管"怎么设计得好"，不管"长什么样"（风格由项目选定一套后贯彻）。流程按**用户带宽经济学**设计：agent 算力免费、用户注意力最贵——决策尽量做成识别题（看图挑），不做成回忆题（凭空想）。全程只有两个用户触点，其余环节用户零感知。对齐原理与带宽账见 [`references/alignment.md`](references/alignment.md)，手艺手法库见 [`references/craft.md`](references/craft.md)。

## 感知四档（每个决策先归档再行动）

| 档 | 内容 | 行动 |
|---|---|---|
| 必须拍板 | 概念/隐喻、风格方向、信息主角 | 触点 1 看图决策，agent 带提案不给开放题 |
| 廉价确认 | 信息架构、适配路线、目标屏 | 给默认+一句理由，不反对即过（并入触点 1 的文字区） |
| 草稿否决 | 动效幅度、状态词、图形调性 | 不单独问，随触点 2 草稿一起给，否决即改 |
| 永不打扰 | 色值、阴影参数、断点数值、字体 fallback、token 命名 | agent 全权，用户零感知 |

## 环节地图（出问题先按此定位）

| # | 环节 | 产出物 | 完成判据 |
|---|---|---|---|
| 0 | brief 理解 | 概念/主角/约束的假设 | 假设明确到能直接做 mockup；缺失项列入触点 1 文字区 |
| 1 | **触点 1：对齐** | 3 个风格发散 mockup 截图 + 一行概念声明 | 用户选定风格或纠正概念；概念、风格、主角三决策一次关闭 |
| 2 | 风格收敛 | 语义 token 定稿（色板四层/缓动/双字体） | 每个色值与动画时长能答出语义；与选中 mockup 一致 |
| 3 | 信息架构 | 栅格与比例（主角区/辅助区） | 25% 缩放或灰度下 3 秒指出主角；一句一强调点 |
| 4 | 组件施工 | 组件实现 | 过 craft.md「质感手法」逐条：用了或明确不用 |
| 5 | 文案 | 全部界面文字 | 无"看起来有信息其实没有"的元素；别人的话与界面的话可辨 |
| 6 | 动效 | 动画与降级 | 关全部动画后状态仍完整可读（decoration, never data） |
| 7 | 适配 | 最小+最大目标屏两截图 | 两张图上主信息都成立 |
| 8 | **触点 2：验收** | 首版全屏截图 + 自查清单结果 | 用户确认或提出修改；反馈（日期+原话+原因）进代码注释 |
| M | 元迭代 | 反例入库 + skill 补丁 | 见末节「元迭代」 |

## 各环节要点

**0. brief 理解**：从上下文抽出概念候选、信息主角、目标场景与硬约束。抽不出的不猜——列入触点 1 让用户一次性补。

**1. 触点 1（唯一的前置打扰）**：做 3 个 mockup——同一概念与主角，风格必须发散（稳/中/野三角），HTML 渲染截图交付；顶上配一行字「我按 X 概念、Y 主角做，看图挑一个或纠正」。风格规格卡（廉价确认档的默认项）随图附上。判据见环节地图；用户回复模糊时不追问，按最贴近解读继续并在设计记录标注假设。

**2. 风格收敛**：从选中 mockup 反解 token：底色阶 5–7 级（带色温，不用纯灰）、内容面 1–2 个明度、强调色 ≤3（各管一个语义）、角色色按实体分配、一条缓动（推荐 `cubic-bezier(.16,1,.3,1)`）、界面字体+内容字体各一。

**3–7. 施工（用户零感知）**：按 craft.md 逐条过手法库。结构先行（先栅格后组件）；质感=物理一致性（阴影画厚度不画浮起、数字 tabular-nums、标题紧排）；文案诚实（空态如实、不编造、没结论就说没结论）；动效只做装饰且可全关；适配二选一（海报式整页缩放 / 断点只减不挤）。

**8. 触点 2（验收）**：全屏截图 + 自查清单（craft.md 12 条）结果一起发。critique 循环到此为止不再新增触点；每条反馈进代码注释。

## 降级规则

- 上下文已锚定概念（明确 brief/既有产品延续）→ 触点 1 可省，直接进环节 2 并在触点 2 一并确认。
- 用户回复模糊（"差不多"）→ 不追问，按最贴近解读做，设计记录标注假设。
- 用户不回 → 概念已锚定才允许按推荐默认继续（标"可推翻"）；概念未锚定则停等——概念错了后面全是浪费。

## 元迭代（实例驱动，skill 自我进化）

每次使用后若出现不满意/返工：**先定位环节，再补规则**，不泛泛改 skill。

1. **定位**：按 `references/alignment.md` 的「失败信号 → 环节」表，把问题归到单个环节（例：风格选错=环节 1/2 的 mockup 或 token 问题；主角不清=环节 3；看着廉价=环节 4 手法缺失；语义误解=环节 0）。
2. **入库**：把该实例提炼成一条反例/规则，补进对应环节的文档（手法库/反模式/判据），写清来源（日期+场景+用户原话）。
3. **升级**：反例攒批后升 skill 版本，改动记 `CHANGELOG.md`（本目录内），规则只增不删——失效规则标注 superseded 不删除。
