# 对齐流程：带宽账、触点设计与失败定位

本文件是对齐过程的设计依据与迭代索引。SKILL.md 的感知四档与两触点流程由此收敛（2026-09-30 与林昊评审收敛，候选方案 A 三闸/B 提案先行/C 规格卡/D 分层默认，B+A 杂交胜出）。

## 带宽账（为什么是两个触点）

用户带宽的三个敌人：触点次数、单次认知翻译成本、决策依据保真度。agent 算力免费、用户注意力最贵——所以一切能转移到 agent 侧的工作都转移：不让用户从文字想象风格（recall，最贵），让用户对着已实现的风格做反应（recognition，每张图 10–30 秒）。

| 候选方案 | 触点 | 风格决策依据 | 用户成本 | 决策质量 |
|---|---|---|---|---|
| A 三闸收敛 | 3 | 文字规格卡 | ~3 分钟 | 中 |
| **B 提案先行（胜出）** | 1–2 | 成稿截图 | ~1 分钟 | 高 |
| C 规格卡确认 | 1 | 纯文字 | ~1 分钟 | 低 |
| D 分层默认+例外 | 1 | 文字清单 | ~30 秒 | 中低 |

收敛形态：B 为主体，折入 A 的廉价概念闸——触点 1 的一行概念声明（「我按 X 概念、Y 主角做」）让概念/风格/主角三个决策在一次看图中同时关闭。

## 触点设计

**触点 1**：3 个 mockup（稳/中/野三角，覆盖风格空间，用户做识别题不是比较题）+ 一行概念声明 + 风格规格卡（廉价确认档的默认项随图附上，选择可追溯）。

**触点 2**：全屏截图 + 自查清单结果。critique 在稿上进行，不再新增触点。

**降级**：回复模糊→不追问，按最贴近解读并标注假设；用户不回→概念已锚定才按默认继续（标"可推翻"），未锚定停等。

## 失败信号 → 环节定位表（元迭代的索引）

| 下游症状 | 问题环节 | 迭代入口 |
|---|---|---|
| "这不是我要的东西" | 0 brief 理解 | brief 抽取规则、触点 1 概念声明写法 |
| "三个都差不多/都不喜欢" | 1 mockup 发散度 | mockup 三角的拉开方式、数量 |
| 选中的稿做出来后"变味了" | 2 token 反解失真 | token 四层结构、语义判据 |
| 不知道先看哪 | 3 信息架构 | 主角判定与层级手法（尺寸/明度/色彩/运动） |
| 看着廉价/像模板 | 4 组件手艺 | craft.md 质感手法库补条目 |
| 分不清谁在说话/文案假 | 5 文案 | 字体分工、状态词、诚实后缀规则 |
| 动效吵/关动画后丢状态 | 6 动效 | decoration-never-data 判据、降级路径 |
| 某目标屏上崩了 | 7 适配 | 海报式 vs 流式的选择依据、断点删减顺序 |
| 用户被问得烦 | 流程本身 | 感知四档归类（是否把"永不打扰"档拿出来问了） |
| 用户一次都没被问就错了方向 | 流程本身 | 降级规则（概念未锚定却省略了触点 1） |
